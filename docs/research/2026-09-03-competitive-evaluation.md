# mgraphctl — competitive evaluation

Subject: `mgraphctl` 0.1.0, released 2026-09-05 as tag `mgraphctl--v0.1.0` (commit 20a1ac7 on `main`), public at github.com/svd/mgraphctl under MIT and on PyPI. Competitor profiles were retrieved 2026-09-03/04 and their live metadata (stars, versions, issue states, npm downloads) re-checked 2026-09-05; mgraphctl facts were first taken at 78438ae on `dev` and re-checked against the release. Basis: fourteen verified competitor profiles and a read-only inspection of this repository. Where the evidence is thin, the text says so; nothing below is asserted beyond what was verified.

Conventions: **implemented** = present in 0.1.0; **[PLANNED]** = specified, not landed; **unverified** = plausible from code reading but never exercised. Grades are A–F on "ready for an agent to run against a corporate tenant", not on ambition.

---

## 1. Executive summary

- mgraphctl is, on the evidence, the only tool in the field that combines a Bash-callable CLI, delegated-only auth, full productivity-surface coverage (123 verbs, mail through Planner/To Do/OneNote/presence/transcripts/search), `--json` on every verb, `--dry-run` on every write, a five-value exit-code taxonomy, a bearer host allow-list, a written untrusted-content rule in the skill, and a 765-case offline test suite. No profiled competitor has more than three of those properties at once.
- The first-party and best-known alternatives are weaker than their reputation: mgc is retired (2026-08-28) and archived with unpatched CVEs; merill/msgraph's code has been frozen since 2026-03-26 and its maintainer left Microsoft; Lokka 2.x is closed source and shipped CVE-2026-58201; `az rest` cannot obtain Mail/Calendar/Chat scopes for a signed-in user at all.
- The two tools a reviewer will ask about first, Microsoft Work IQ and the Anthropic Microsoft 365 connector, are both cloud-proxied, delegated-only, Global-Admin-gated, and have no Planner/To Do/OneNote/presence; Work IQ additionally needs a Copilot Credits billing policy. Softeria's ms-365-mcp-server is the only feature-parity peer, and it is an MCP with a ~2 MB tool list, not a CLI.
- Engineering quality is high where it is measurable: layering enforced by tests, idempotency-aware retries, a uniform pagination envelope, best-in-field bearer-leak protection (grade A), and error taxonomy (grade A). Tokens rest in the OS keychain through `keyring`, with a warned 0600-file fallback and `logout` clearing both (B+; the Windows chunked path is tested but has never run on Windows). The weak leg is prompt-injection posture (skill rule only, no content fence, no code-enforced write gate, B-).
- Distribution is built and exercised once: GitHub Actions CI on Python 3.11–3.13, a tag-driven Release workflow with PyPI Trusted Publishing, the repo as its own Claude Code marketplace. The `mgraphctl--v0.1.0` tag ran the workflow green and produced the PyPI package (wheel and sdist) and a GitHub Release with the CHANGELOG notes.
- The main adoption step for anyone outside the author's tenant is the client id: there is no shared app, so `login` works only after the user registers their own Entra public-client app and sets `client_id` (`config set client_id`, or `MGRAPHCTL_CLIENT_ID`). Since 0.1.0 the README documents that step and `login`/`status` refuse the placeholder with `error[CONFIG]: client_id is not set` and a hint, instead of an Entra error. On the author's tenant the default 23-scope set needed admin consent once; after that, login and data commands work. Other tenants' consent policies may differ.
- Still open after 0.1.0: cap `api --all`, run login and the keychain store on Windows and a headless Linux host, add a code-enforced read-only mode, and decide whether to ship a multi-tenant client id.
- Expected traction now that the package, the plugin install and the client-id path exist: on the order of 100–400 stars and low-thousands of monthly downloads within six months. This is an estimate extrapolated from merill/msgraph (111 stars), Lokka (295), Softeria (950), mog (64), o365-cli/mg-api/graph-cli (0), not a measurement.
- Maintenance is the long-term risk: bus factor of one, a date-frozen dependency resolution (`exclude-newer = 2026-09-01`) with no advisory feed, and Graph churn (`sharedWithMe` retirement Nov 2026, `/me/people` maintenance mode, Planner premium). Budget roughly one maintainer-day a month post-launch or expect the decay pattern seen in mog and merill/msgraph.

### 2.2 Other tools in the field, ranked by relevance

1. **Microsoft Work IQ CLI + MCP (`@microsoft/workiq`)** — the official first-party agent path to M365 (mail, calendar, Teams, files, people, Copilot semantic `ask`). GA 2026-06-16; 990 stars; ~37k npm downloads/month. Closed-source .NET binaries proxied through `workiq.svc.cloud.microsoft`; delegated-only ("App-Only is never going to happen"); needs Global Admin consent to ~21 scopes, a provisioned service principal **and** a Copilot Credits spending policy, otherwise every data call is 403 (issue #148, open since June). No device code, no GCC, mutations off by default, 88 open issues, no release since GA. This is the benchmark any Graph CLI for agents must be positioned against.
2. **Anthropic Microsoft 365 connector (claude.ai)** — the zero-install baseline every claude.ai Team/Enterprise user already has: mail/calendar/Teams-chat/SharePoint search and read, transcript-by-event, plus admin-gated writes (mail, calendar, files) since 2026-07-07. No Teams send, no attachments, no Planner/To Do/OneNote/presence/directory search, no raw Graph, Global Admin tenant consent, data transits Anthropic US infrastructure, not usable from Claude Code with API-key auth. It does **not** provide meeting summaries: Teams recap/.loop content is unreadable through it; only transcript-by-event is obtainable.
3. **Softeria ms-365-mcp-server** — the most-used community M365 MCP: 950 stars, ~170k downloads/month, v0.149.1 on 2026-09-03; 332 generated tools across mail, calendar, OneDrive, Excel, OneNote, To Do, Planner, Teams chats/channels/meetings/transcripts, presence, SharePoint lists, Search. `--read-only`, presets, regex tool filtering, discovery mode, opt-in `MS365_MCP_REQUIRE_CONFIRM`, AES-GCM token cache, audit log, ~820 tests, several releases per week. One advisory (GHSA-9w34-3f56-vwmh, `.env` command injection, fixed 0.137.0); the ~2 MB tool list overflows some hosts.
4. **Microsoft Agent 365 Skills + Agent 365 / Work IQ remote MCP servers** — Microsoft's own Claude Code / Copilot CLI plugin precedent (dual marketplace manifests, per-skill hooks, `allowed-tools`, eval fixtures) and tenant-hosted per-workload servers (`mcp_MailTools`, `mcp_TeamsServer`, ...). Useful for packaging conventions; prerequisites (Agent 365 tenant, E5/E7 + Copilot licences, `a365` .NET tool, Global Admin per server) are exactly what a delegated CLI avoids. Preview-only, 36 stars, last commit 2026-07-22.
5. **Direct peers of mgraphctl** (all small, all instructive): **mog/mogcli** (visionik/mogcli, Go, 64 stars, last push 2026-03-06; slug IDs, `--ai-help`; `mail search` broken since May; no Teams/transcripts/presence; PRs unanswered since June; no LICENSE file). **o365-cli** (Python, 0 stars; closest scope match incl. chats and OneDrive `.vtt` transcripts; MCP misreports failures; no `--json`). **mg-api** (Node, 0 stars; registry-as-single-source-of-truth driving `schema`, `--help`, SKILL.md and tests — the best skill/CLI-parity design reference; but auth is Playwright token scraping and most reads hit the decommissioned Outlook REST v2). **graph-cli (afroze9)** (.NET, 0 stars; presence + To Do + chats + SharePoint pages with built-in MCP, per-profile accounts, recipient allow-list; no paging, no tests, vulnerable Kiota CVE-2026-44503).
6. **aren13/m365ctl** (Python, PyPI, Apache-2.0) — a single-author admin CLI (`m365ctl <domain> <verb>`) for OneDrive/SharePoint and Exchange mail over Graph, with local DuckDB catalogs, a plan-file bulk workflow, an append-only JSONL audit log and `m365ctl undo`. Born as an internal one-tenant tool ("fazla-od"), it went public 2026-04-23, cut 24 tags to v1.15.0 in eight days, and has had no commits since 2026-05-01 (1 star, 0 forks, no external contributors, ~19 PyPI downloads/month). It matters as the only other Python Graph CLI in the field and the only profiled tool with dry-run as the *default* on every mutation plus a code-enforced write gate (`--confirm`, allow/deny lists, /dev/tty-only prompts, typed-phrase hard deletes), 999 mocked tests and a 6-cell CI matrix — but it covers only mail and OneDrive, has no calendar/Teams/people/raw passthrough, emits raw HTML bodies, and requires your own single-tenant Entra app with a self-signed certificate.
7. **Also in the field, not profiled in depth**: **ryaker/outlook-mcp** (435 stars, most-starred community Outlook MCP); **floriscornel/teams-mcp** (135 stars; chats, channels, search, presence); **InditexTech mcp-teams-server** (396 stars, best-maintained Teams channel MCP); **nitin27may/ms-graph-mcp** (85 tools incl. Planner/OneNote — a useful coverage checklist); **Himalaya** (7.2k stars, Rust, Graph mail backend, noun-verb grammar — closest mail-CLI design analogue); **bcharleson/ms365-cli** (one registry serving CLI + MCP); **Andrew-Girgis/microsoft-workspace-skill** (28 stars; script-backed SKILL.md, closest skill-not-MCP peer); **md365** (sync-to-Markdown alternative); **ms-365-21v-mcp-server** (policy-aware OAuth 2.1 gateway, sovereign-cloud pattern); **PowerSkills** (wraps Work IQ CLI in a SKILL.md — packaging precedent); **lionello/onedrive-cli** (171 stars), **onenote-cli**, **gcalcli**, **Composio** toolkits, **okapi-ca/ms-365-admin-mcp-server**; **mrhah/m365-cli** and **msgcli**; **Google Workspace `gws`** (30.7k stars; JSON envelope, `--page-all`, `schema`, `--dry-run`, `--sanitize` — the strongest cross-vendor design analogue); **slackcli** (`--read-only` flag, directly relevant to gap #1 in §6). ### 2.3 The predecessor: the Node `msgraph` skill

mgraphctl is an independent Python re-implementation of the feature set of a Node `msgraph` Claude Code skill distributed through a private marketplace: plugin 0.1.0, single `scripts/msgraph.js` (~125 KB), SKILL.md indexing Profile & Org, Emails, Calendar, SharePoint, Teams (chats and channels), Transcripts, OneDrive, OneNote, Planner, To Do, People & Contacts; `--json --meta` envelope; `emails --read --text`; `transcripts --speakers` and `--insights`; `chats list --since`, `--before` and channel-message windowing; `MSGRAPH_CLI` override for out-of-plugin callers; 9 evals; a `node --test` suite of 76 tests. Known quirks mgraphctl's design spec set out to fix: data commands can open a browser, UTC datetimes mislabelled, inconsistent exit codes (including exit 0 when not logged in). No presence noun and no dry-run in its SKILL.md index. It authenticates as an app registered in the corporate Entra tenant with admin consent, requesting the same 23-scope default set mgraphctl uses.

### 2.4 Recommendation by use case

- **Agents (Claude Code, Codex, Copilot CLI, custom harnesses)**: mgraphctl. Position explicitly against Work IQ and the Anthropic connector, both of which need more admin action, not less.
- **Admin and SharePoint scripting**: m365.
- **One-off raw calls**: `Invoke-MgGraphRequest` or `mgraphctl api`.
- **Directory reads only**: `az rest`.
- **Endpoint lookup while constructing `mgraphctl api` calls**: merill/msgraph's offline indexes.
- **Lokka**: drop. Raw passthrough with no helpers, no paging, no dry-run, beta by default, closed source, one SSRF CVE.

Caveat: mgraphctl's default-scope set needed admin consent once on the author's tenant (Mail.Read, Calendars.*, Chat.Read, Sites.*.All fall under the Microsoft-managed default policy), and the extended and on-demand scopes certainly need it. That is the same organisational gate the alternatives face, and a lighter one than Work IQ's or the Anthropic connector's.

### 3.4 What mgraphctl has that no profiled competitor has

- **Plan-rendering `--dry-run` on all 37 write verbs and non-GET `api`**, showing method/URL/headers/body including multi-step plans with `{draftId}`/`{chatId}`/`{etag}` placeholders. Nearest analogues: m365ctl (dry-run by default with plan files, but no HTTP plan rendering and mail/OneDrive only), PowerShell `-WhatIf` (generated cmdlets only), o365-cli (two verbs), and among mention-only tools JayRHa MicrosoftGraphCLI and @fateforge outlook-cli.
- **Local pre-request scope gate with tiered scope sets** (default 23 / extended +10 / on-demand `--scope`), `MISSING_SCOPE` naming the exact `login` command and `CONSENT_REQUIRED` emitting the tenant admin-consent URL. Others request at login or react after a 403; Softeria's tool-derived scopes are closest.
- **Five-value exit taxonomy** (0; 1; 2 usage/AMBIGUOUS; 3 auth; 4 NOT_FOUND) with an `error[CODE]` + `hint:` stderr block. mg-api has 0/1/2; mgc maps exit codes from ODataError; the remaining hand-written CLIs in evidence are 0/1 (m365 and graph-cli exit-code behaviour was not assessed).
- **Agent-facing text pipeline**: HTML→Markdown for mail/Teams/OneNote with `<at>`→@Name, `[attachment: ...]`, `[image: hostedContents/<id>]` markers; local VTT→`[HH:MM:SS] Speaker:` with `--speakers` turn merging and attribution fallback; `Prefer: outlook.timezone`; body caps. Other tools have lighter text modes (mog html→text, o365-cli html2text, graph-cli chat HTML stripping, m365 text/csv/md, Work IQ `ask` markdown, Softeria `Prefer: outlook.body-content-type=text`); none does the full conversion with markers.
- **Display-name resolution across ten nouns** with deterministic `NOT_FOUND` (4) vs `AMBIGUOUS` (2, candidates on stderr). Analogues exist (mog slugs, graph-cli local caches, m365 `--folderName`/team/channel names, Softeria `parse-teams-url`, Work IQ resolve-then-act) but were not assessed for the ambiguity contract.
- **Test-enforced surface/doc parity**: every registered verb must have a `@covers` test and `--json` (`test_surface.py`) and a commands.md heading (`test_docs.py`); the five version strings must agree (`test_version.py`); httpx record/replay transport. mg-api's SKILL.md-equals-registry check is the closest analogue.
- **Composite verbs**: `chats dm` find-or-create, `todo from-mail`, `meetings list --subject --resolve --with-transcripts` ($batch), `meetings insights` v1.0→beta probe with soft 403, `sharepoint url` share-link resolution, `mail mark` multi-id via $batch.
- **Layered configuration with provenance**: flag > `MGRAPHCTL_*` env > `~/.mgraphctl/config.toml`, and `config show` prints where each effective value came from. m365ctl has a config file; no other peer reports the source of a setting.

### 3.5 What others have that mgraphctl lacks

Explicit non-goals (design spec), implemented elsewhere: app-only/certificate/MI/federated auth (m365, PS, az, mgc, merill, Lokka); MCP exposure (Softeria, Lokka, Work IQ, o365-cli, graph-cli, PnP companion); delta/subscriptions (Softeria, PS, m365); sovereign clouds, multi-account, Windows shim, `Prefer: IdType=ImmutableId`.

Not in mgraphctl and not scheduled: machine-readable schema/registry for agents (mg-api `schema`, Work IQ `get_schema`, merill FTS indexes, Find-MgGraphCommand) — mgraphctl has `--help` and prose only; global client-side projection (`--query` JMESPath in mgc/m365/az) — mgraphctl has `--select` on `mail list` and `--fields` on `search` and `sharepoint items`; binary-enforced read-only/allow-list modes (Softeria, merill, Lokka, graph-cli, Work IQ policy, slackcli `--read-only`); Copilot semantic `ask`/retrieval (Work IQ, Copilot MCP) — not achievable over Graph alone; Excel workbook ops (mog, Softeria); contacts write (mog, m365, o365-cli, Softeria); mail-rule/category writes (Softeria); Teams management (channel/team create, members, reactions, images, quoted reply — Softeria, graph-cli, m365); call records / attendance (Softeria, m365); group-scoped Planner/OneNote/calendar (PS, Softeria); a shipped app registration (every first-party and most community tools).

Gaps vs the Node predecessor: one-shot `--insights` by subject (mgraphctl needs the meeting id from `meetings list` first). Everything else the Node skill indexed — `--meta`-style envelope, `--speakers`, `chats list --since`, channel windowing — is present.

### 4.2 Tests and CI — A-

765 pytest cases, fully offline (respx + JSON fixtures; an in-process fake `keyring` backend for the token store); `test_surface.py`, `test_docs.py` and `test_version.py` enforce verb/`--json`/doc/version parity; ruff check + format over 92 files; no mypy/pyright despite full annotations. `.github/workflows/ci.yml` runs on every push and PR: pytest on Python 3.11/3.12/3.13 (ubuntu-latest only), `uv lock --check`, ruff check and format, `uv build` + `twine check --strict`, and `scripts/scan_secrets.py`. The autouse fixture pins `MGRAPHCTL_CONFIG`, `MGRAPHCTL_TOKEN_CACHE`, `MGRAPHCTL_TOKEN_STORE` and, since 0.1.0, `MGRAPHCTL_CLIENT_ID` (a test id), so a developer's exported client id no longer changes results; the remaining `MGRAPHCTL_*` names (`TENANT_ID`, `RETRIES`, `TIMEOUT_MS`, `RETRY_BASE_MS`) are still inherited. Peers: m365 (1,087 spec files, 100% c8 gate, 3-OS matrix), Softeria (~821 vitest, Node 18/20/22) and m365ctl (999 tests, ubuntu/macos × 3.11–3.13, mypy) are the comparables; mgc had Azure Pipelines + CodeQL while alive; merill runs build + vet but never `go test`; graph-cli has only a tag-triggered publish workflow; Lokka, mog, o365-cli, mg-api have no CI. ### 4.3 Code layering — A-

`commands/*` (typer, <=~40 lines, no HTTP, return Result dataclasses) → `graph/*` (pure: client + params in, dicts/PageResult/Plan out, raise only `errors.*`) → `http.GraphClient` (only httpx user); `render.emit` is the sole stdout writer. Verified: `graph/*` import no httpx and never print; side effects via injected callbacks (planner, chats). Debt: identical `_run(client, plan)` in `graph/files.py:152`, `graph/planner.py:44`, `graph/todo.py:25`; `JSON` header dict and `_FRACTIONAL_RE` duplicated across graph modules; no shared `graph/_common.py`. Only mg-api's registry-drives-everything design and Softeria's declarative `endpoints.json` are comparably disciplined; mgc is 14k generated files, m365 is 2,560 command classes mid-Zod-migration.

### 4.4 Auth and token security — B+

Flow: msal PublicClientApplication; interactive loopback (prompt=select_account, `--force` → prompt=login, 300 s → LOGIN_TIMEOUT) or device code; data commands use `acquire_token_silent_with_error` only, so no browser is ever opened by a data command; scope gate before any request; consent → admin URL.

Storage (`token_store.py`, `auth.py`): the serialized msal cache is one `keyring` item (service `mgraphctl`, account = the cache path, so two cache paths stay two sign-ins) in the macOS Keychain, Windows Credential Locker or Linux Secret Service. `token_store = auto | keyring | file` (config or `MGRAPHCTL_TOKEN_STORE`). Under `auto` the store is chosen by asking `keyring` for its backend and rejecting the `fail` and `null` placeholders, so a host with no keychain gets the 0600 file in a 0700 directory silently; a keychain that exists but fails at read or write time (locked, denied, no session bus) flips the process to the file with one stderr warning. `save_cache` never raises; `logout` clears the keychain item and any file, whichever store is selected. A `token_cache.json` left by an earlier version is imported on the first run and unlinked only after the keychain write succeeds. Windows caps a credential at 2560 bytes, so the item is split into 1000-character chunks with a head record written last; that path is covered by the fake-backend tests and has never run on a Windows machine (the README advertises Windows via raw `uv run`, and `tzdata` is a Windows-only dependency, so the platform is intended). `login`, `status` and `logout` print the store in use and carry a `store` field in JSON. Two design points worth a second look: `auto` announces nothing when it settles on the file, so an agent on a CI box holds a plaintext refresh token without a hint unless it runs `status`; and keyring writes are last-writer-wins with no lock, the same as the file's `os.replace`.

Client id: `config.CLIENT_ID_DEFAULT` is `00000000-0000-0000-0000-000000000000` and there is no shared app. Since 0.1.0 `auth.app()` refuses that value with `error[CONFIG]: client_id is not set` (exit 2) and a hint naming `config set client_id` and `MGRAPHCTL_CLIENT_ID`, so `login`, `status` and every silent acquisition fail locally instead of at Entra with AADSTS700016. The README's "First run and login" section documents registering a public-client app, and the SKILL.md and commands.md env tables list the variable as "none; required". A working install still needs a user-registered app with the redirect URI the loopback flow uses.

Field: mgraphctl joins mgc, Graph PS, merill, Softeria and graph-cli in keeping the refresh token out of plaintext; m365, mog, o365-cli, m365ctl and az-on-Linux still write it to disk, and mg-api's Playwright token scraping is the floor. Softeria's GHSA-9w34 (`.env`-driven command execution) is a reminder that config paths are attack surface; mgraphctl's env-and-TOML config executes nothing from either, which is narrower and good.

### 4.5 Bearer-leak protections — A

`_ensure_bearer_host` inside `_build` requires https and host in the configured allow-list, so nextLinks, `api GET https://...` and hosted-content URLs are all checked (tests in `test_http.py`). Redirect targets and upload-session PUTs use a separate `_plain` client with no Authorization. Hosted-content URLs must match `^/chats|teams/.../hostedContents/<id>/$value`. Fixture transport refuses login.microsoftonline.com and never records Authorization/Set-Cookie. `-dd` body logs redact tokens. Image srcs in bodies are rendered as markers, never fetched.

Field: m365 `request` sends the bearer to whatever `--resource` names; Graph PS `Invoke-MgGraphRequest` re-targets to any absolute URI; merill `buildURL` attaches the bearer to any absolute URL; az rest only got `is_same_origin` in 2.88.0 (PR #33511); Lokka's Azure RM path concatenation was CVE-2026-58201; graph-cli has `AllowedHostsValidator` but carries Kiota GHSA-7j59 transitively. mgraphctl is the only tool with an escape hatch that host-gates it at build time. Any future `--beta`/sovereign work must extend the allow-list, not bypass it.

### 4.6 Retry and throttling — A-

RETRY_STATUSES {429, 503, 504}, attempts configurable via `MGRAPHCTL_RETRIES`; Retry-After as delta-seconds or HTTP-date, capped 300 s; else exponential backoff with jitter. Non-idempotent methods replayed only on connect-phase failures, so `/sendMail` is never double-sent (tests in `test_http.py`). 401 → exactly one forced refresh. `$batch` chunks of 20, sub-429 resubmitted with max Retry-After, missing sub-responses synthesised as HTTP_502 (`http.py:586-650`). Gaps: batch 503/504 sub-responses are returned as errors immediately rather than resubmitted; a naive `parsedate_to_datetime` result raises TypeError that is swallowed, silently ignoring the header (`http.py:401`); planner 412 retried once, others not. Field: SDK middleware in mgc/PS/graph-cli; m365 429/503 in request.ts; mg-api 429 + sockets (regardless of idempotency); az rest, merill, mog, o365-cli, Lokka: none.

### 4.7 Pagination and truncation — A-

`GraphClient.paginate(limit, all_, cap, page_size)` → `PageResult(items, truncated, pages)`; `--limit`/`--all` mutually exclusive; per-noun caps (mail 500, chats 200, drive 1000, members 999); text prints "(more results available ...)" / "(hit the N-item cap ...)" to stderr, JSON carries `{items,count,fetched,cap,truncated}` plus `window` and `query` where applicable, with `fetched` counting what Graph returned before client-side filters. Holes: `api --all` uses `PAGE_CAP = sys.maxsize` (`commands/api.py:17,136`) and emits `{value:[...]}` instead of the list envelope; planner slices client-side after fetching all; underscore-prefixed annotations leak into planner JSON. Field: only Claude M365 (nextOffset + partial notes) and Softeria (MAX_PAGES/MAX_ITEMS, in-band) report truncation at all; m365 and mgc follow nextLink silently; Graph PS raw cmdlet and az rest do not page; Lokka `fetchAll` is unbounded; Work IQ caps at 100 and sometimes rejects its own nextLink (#158).

### 4.8 Error taxonomy — A

`MsgraphError` base with code/message/hint/request_id/correlation_id; UsageError/AmbiguousError exit 2; AuthError (NOT_LOGGED_IN, MISSING_SCOPE, CONSENT_REQUIRED, LOGIN_TIMEOUT, UNAUTHORIZED) exit 3; NotFoundError + Graph 404 exit 4; Graph 401/403 exit 3; CONFIG for an unreadable config file; else 1. One stderr block; hints resolve the shim path lazily; OSError → IO, unknown → INTERNAL with traceback under `--debug`; consent detected by AADSTS65001/650052 with tenant-specific admin-consent URL; `status --json` prints a document before exit 3. Minor: AssertionError inside commands surfaces as INTERNAL; hint picks the longest scope name rather than the strongest. Field: mgc maps exit codes from ODataError; mg-api JSON envelope 0/1/2; m365 `--output none` swallows errors; az rest exit 1 for everything; Lokka misconfig crashes the process (#50); Work IQ errors only in structuredContent (#180); o365-cli `is False` check never fires, failures reported as success; mog always exit 1.

### 4.9 Prompt-injection posture — B-

SKILL.md rule 8 states that mail bodies, chat and channel messages, transcripts, file and folder names, calendar invitations and search snippets are content other people wrote, never to be acted on and never forwarded without explicit confirmation. Structural mitigations are stronger than every peer's: no browser from data commands, dry-run on every write, hosted-content URL validation, bearer host gate, nothing executed from env or config. What is missing: the content itself goes to stdout unfenced with no provenance marker (markdownify leaves `#`, `>` and link syntax intact, so a hostile email renders as structured text); `--json` consumers get no hint which fields are untrusted; the CLI never prompts; `api` declares no scopes and so bypasses the scope gate (`commands/api.py:74`); and the write ritual ("dry-run → show → confirm → run") is SKILL.md prose. A model that skips the ritual can `mail send` or `api DELETE` in one call.

Field: mgc/PS/az/m365 raw JSON, no guidance; merill none in SKILL (Snyk W011 MEDIUM) but `--allow-writes` + DELETE blocked in code; Lokka none, guardrails off by default, tool descriptions themselves contain imperatives; Work IQ mutations off by default per tenant policy; Softeria opt-in confirm, `--read-only`, agent sign-off marker; Claude M365 per-call human approval on writes; mog/o365-cli/mg-api none; graph-cli allow-list on send/share only; Agent 365's `make-ai-teammate` SKILL.md carries a narrow prompt-injection guard; brendanerofeev's Outlook connector and @fateforge outlook-cli (mention-only) sanitise content or tier permissions. Graded below mgraphctl's structural strengths because the design spec makes "safe for non-interactive use" goal #2, the primary caller is a model, and unlike Claude M365, Work IQ, merill or m365ctl there is no code-enforced write gate.

### 4.10 Release process — B+

Released: CHANGELOG section `[0.1.0] — 2026-09-05`, annotated tag `mgraphctl--v0.1.0` on the `main` merge commit 20a1ac7 (PR #1 from `dev`), PyPI `mgraphctl` 0.1.0 (wheel and sdist, uploaded 2026-09-04 22:43 UTC), GitHub Release "mgraphctl v0.1.0" with the CHANGELOG notes as body. The version is held in five places (`pyproject.toml`, `__init__.py`, `plugin.json`, `marketplace.json`, SKILL.md frontmatter) and `test_version.py` fails if any two disagree. `.github/workflows/release.yml` fires on `mgraphctl--vX.Y.Z` tags: requires an annotated tag, checks the tag against `plugin.json` and `pyproject.toml`, `uv lock --check`, runs the suite, `uv build` + `twine check --strict`, `uv publish --trusted-publishing always`, then a GitHub Release with notes extracted from the CHANGELOG section (fails if the section is missing). The 0.1.0 run passed every step, so the PyPI Trusted Publisher and the `pypi` environment are configured. Procedure documented in `.claude/skills/releasing-a-version` and `VERSIONING.md`; `main` accepts only merge commits from `dev` via PR. Reproducibility strong: committed uv.lock, `[tool.uv] exclude-newer = 2026-09-01`, shim runs `uv run --frozen --no-dev`, venv outside the plugin dir. Not done: the real-account flow (status → login → data commands) has been exercised on one tenant on macOS but is not a recorded release check; no first-run shim timing; no signed artifacts or SBOM; no Windows run. Field lessons from peers with real users: merill's unsigned binaries, mog's stale `@latest`, mgc's never-shipped security release, Work IQ's `preview` dist-tag pointing at an unsupported build — the first release is where process gaps surface, and mgraphctl's went through without one.

### 4.11 Maintenance risk — B-

Public repo with CI, a secret scanner and a version gate is a structural advantage over every hobby peer. Within that: bus factor of one; `exclude-newer` freeze with no owner or advisory feed (msal/httpx security releases stop flowing, the same way mgc's unmerged dependabot PRs did); no `SECURITY.md`, no Dependabot/Renovate; 46 locked packages incl. two HTTP stacks and `keyring`; documented fragilities (insights beta probe, `/me/people` maintenance mode, `sharedWithMe` deprecation Nov 2026, OneNote `$search`); two spec open points unresolved against a real tenant (Group.Read.All vs TeamMember.Read.All, Conditional Access blocking device code); Windows unverified. Peers: m365 healthy but v12 breaking; Graph PS Microsoft-maintained with 200 open issues; merill frozen; Lokka closed and self-declared not production-ready; Work IQ closed and cloud-proxied with 88 open issues; Softeria very active but one maintainer at 62% of commits; mog/o365-cli/mg-api/graph-cli abandoned or opportunistic.

## 5. Potential usage and community value / Польза для комьюнити

### 5.1 Bottom line

mgraphctl fills a real gap: mgc is gone, m365 is admin/SharePoint-heavy and needs a registration, merill/msgraph is a docs index with a raw executor, Lokka went closed, Work IQ needs Copilot billing and a Global Admin, the Anthropic connector has no Teams write, no Planner/To Do/OneNote/presence and no scripting surface, and Softeria is an MCP, not a CLI an agent can call in Bash. Licence (MIT), a public repository that is its own Claude Code marketplace, and a PyPI release pipeline are in place. Two facts bound the community value today:

- **Client id**: no shared app ships. The README walks a user through registering a public-client app and setting `client_id`, and the CLI refuses the placeholder with a `CONFIG` hint. Sign-in for strangers therefore works, at the cost of an Entra app registration per tenant. That registration is now the single largest adoption barrier.
- **Readiness**: released. 0.1.0 is tagged, on PyPI and in GitHub Releases, and the plugin install pins the tag. "Value delivered immediately" applies to anyone who can register an app.

### 5.2 Who would adopt it

1. **Claude Code users in organisations on Microsoft 365** (primary). Install is two commands (`claude plugin marketplace add svd/mgraphctl`, `claude plugin install mgraphctl@mgraphctl`), after which the shim builds the venv on first use. On the author's tenant the default set needed one admin consent; expect the same elsewhere. Realistic ceiling in the first quarter: tens to low hundreds of users, bounded by discovery and by the client-id step.
2. **Agent builders who need a Bash-callable, token-lean M365 tool** (Claude Code, Codex, Copilot CLI, OpenClaw, custom harnesses). Currently served by Softeria (~170k downloads/month) and Work IQ (~37k/month). mgraphctl's differentiators: Markdown bodies with caps, `truncated` reporting, `--dry-run` plans, exit-code contract, no-browser guarantee, written untrusted-content rule. This is where community value is largest; the CLI-vs-MCP token argument and `gws` (30.7k stars) proving the pattern for Google are the pitch. No mgraphctl token measurement exists yet; produce one before making the claim publicly.
3. **Python shops wanting a scriptable delegated Graph CLI after mgc's retirement.** Microsoft's answer is PowerShell; `az rest` cannot get Mail/Calendar/Chat scopes with a user login (#22775). A `pipx`/`uv tool install`-able CLI with `--json`, retries, `$batch`, upload sessions fills that hole, and 0.1.0 is on PyPI. The one Python Graph CLI already on PyPI, aren13/m365ctl, covers mail and OneDrive only, needs your own Entra app plus a certificate, and has been idle since 2026-05-01 at ~19 downloads/month — it neither serves this segment nor blocks mgraphctl from doing so, though its dry-run-by-default and code-enforced write gate are the bar a security reviewer will hold mgraphctl's prose-only write ritual against.
4. **People who specifically want transcripts / chats / Planner / To Do verbs in a CLI.** m365 has chats/Planner/To Do/transcripts and Graph PowerShell has all four; the niche is "those verbs in a small, delegated, agent-shaped CLI". Among the small peers (mog, o365-cli, mg-api, graph-cli) each misses two or more.
5. **Not a target**: tenant admins (m365, Graph PS, wyre m365 plugin), Copilot-semantic search users (Work IQ, m365copilot-mcp), consumer MSA accounts (explicit non-goal).

Traction reference points (measured): merill/msgraph 111 stars / 1,145 skills.sh installs in six months with a famous author and near-zero code maintenance; Lokka 295 stars / ~2k npm downloads a month; Softeria 950 stars / ~170k downloads a month after 17 months of several releases per week; mog 64 stars; o365-cli 726 downloads total; mg-api and graph-cli 0 stars. **Estimate, not measurement**: with the client-id path documented and the PyPI package out, a well-launched mgraphctl plus a skills.sh entry could land 100–400 stars and 1–5k downloads/month within six months; if the app-registration step deters most visitors it lands where o365-cli did.

### 5.3 Barriers

| Barrier | Severity | Notes / mitigation |
|---|---|---|
| No shared client id; BYO app registration required | **high** | 0.1.0 took the BYO path: the README documents registration and `login` fails fast with a `CONFIG` hint on the placeholder. Still open: the README does not name the loopback redirect URI or the public-client flag the registration needs; and whether to register a multi-tenant public-client app and ship its id as the default (the Lokka `a9bac4c3` trust problem applies: external tenants consent to a third-party app). Reconsider the first-party "Microsoft Graph Command Line Tools" id `14d82eec-...` (used by mgc, Graph PS, merill; pre-consented in many tenants); the design spec rejected it — record any reversal. |
| Admin consent for default and extended scopes | medium | The default set needed admin consent once on the author's tenant (Mail.Read, Calendars.*, Chat.Read, Sites.* fall under the Microsoft-managed default policy); P2 verbs (TeamMember.Read.All, OnlineMeetingTranscript/Recording, Presence.*, MailboxSettings.ReadWrite, Chat.Create) certainly do. The CLI emits the admin-consent URL. Ship a one-page "what to ask your admin for" doc and a `status`-style scope report. |
| `uv` + Python 3.11+, 10–40 s first run (estimate) | medium | Corporate proxies and locked-down machines can break `uv python install`. Publishing to PyPI makes `pipx`/`uv tool install` the documented human path and lets the shim `uvx` a pinned version later. |
| No Windows shim; Windows never run | high | Windows advertised in README (direct `uv run` invocation) but never run. Add a `.cmd`/PowerShell shim, run pytest on `windows-latest`, exercise login and the chunked Credential Locker item there. |
| Keychain on headless hosts | low | Linux CI runners and SSH boxes often lack a Secret Service; `auto` then uses the 0600 file silently and `status` reports it. Documented in the README; consider a one-line notice on `login` when the file is chosen. |
| No skills.sh / agentskills.io listing | low | The repo already carries `.claude-plugin/marketplace.json`; an `npx skills add` layout is a small addition now that a tag exists. |
| No `SECURITY.md`, no dependency advisory feed | low-medium | Add `SECURITY.md`; give `exclude-newer` an owner and cadence or add `pip-audit`/`uv audit` plus Dependabot for msal/httpx/cryptography. |

### 5.5 Naming

`mgraphctl` is held by this project on PyPI since 0.1.0 and distinct from merill/msgraph (Go CLI + skill, skills.sh slug `merill/msgraph/msgraph`, graph.pm, now a Jozra product), from the Node `msgraph` skill it re-implements, and from Microsoft's `msgraph-sdk-*`, `msgraph-cli`, `msgraph-core` namespaces. Console script, plugin name, skill directory, `MGRAPHCTL_*` env vars and `~/.mgraphctl/` all agree. Not yet checked: npm, Homebrew and skills.sh for the same string.

### 5.6 Risks to the recommendation

- Microsoft may add Planner/To Do/OneNote to Work IQ and relax its billing/consent friction; that erodes segment 2 but not segments 1 and 3.
- Graph churn is the main maintenance tax. Without roughly one maintainer-day a month the project decays like mog and merill/msgraph did within six months.
- A shipped multi-tenant client id makes the author the app owner every tenant consents to; a BYO-only path caps adoption at people willing to register an Entra app. There is no third option.

## 6. Gaps and prioritized next steps

### 6.1 Implemented in 0.1.0

123 verbs across the productivity surface; OS-keychain token store with file fallback and migration; placeholder client id refused with a `CONFIG` hint and BYO registration documented in the README; `--json` on all verbs with a uniform list envelope; `--dry-run` on all 37 write verbs and non-GET `api`; tiered scope gate with `MISSING_SCOPE`/`CONSENT_REQUIRED`; five-value exit taxonomy; bearer host allow-list and two-client split; idempotency-aware retries and `$batch` 429 resubmit; configurable retries and timeouts; HTML→Markdown and VTT pipelines with `--speakers`; display-name resolution; `~/.mgraphctl/config.toml` with `config init/set/unset/show/path`; SKILL.md untrusted-content rule; 10 evals; 765 offline tests with surface/doc/version parity enforcement; GitHub Actions CI; tag-driven Release workflow with PyPI Trusted Publishing, run once end to end (tag → PyPI 0.1.0 → GitHub Release); MIT licence; uv.lock + `exclude-newer` + frozen shim; marketplace entry; documented release procedure.

### 6.2 Prioritized gaps (ordered by risk; all **[NOT DONE]** unless stated)

1. **Client id.** **[PARTLY DONE in 0.1.0]**: `login` refuses the placeholder with a `CONFIG` hint, the README documents BYO registration, SKILL.md and commands.md no longer call the default "the shared public client id". Remaining: state the loopback redirect URI and public-client flag the registration needs; decide whether to also ship a multi-tenant public-client app id.
2. **No code-enforced boundary between untrusted content and the agent, and no write gate outside SKILL.md.** Fence untrusted bodies in text output with provenance (`--- begin message body (untrusted, id=...) ---`); document that `--json` consumers must treat `body`, `bodyPreview`, `content`, `subject`, `displayName` as untrusted strings; consider `--sanitize` (as `gws` does) and a code-level `MGRAPHCTL_READ_ONLY=1` / `--allow-writes` mode (merill, Softeria, slackcli pattern). Route `api` through the scope gate or document explicitly that it bypasses it.
3. **Exercise the keychain store off macOS.** Run login → `status` → `logout` on Windows (chunked Credential Locker item, test-only today) and on a headless Linux host (`auto` → file, silent). Decide whether `login` should say so when `auto` settles on the file. The design spec's non-goals line still lists keychain-backed storage; the note beneath it overrides it, so fold the two.
4. **`api --all` unbounded and shape-inconsistent; batch retries incomplete.** Cap `api --all` at 1,000 (the largest existing per-noun cap) and return the standard list envelope; retry 503/504 inside `$batch`; treat a naive Retry-After date as UTC; strip underscore-prefixed annotations from planner JSON.
5. **Release readiness.** **[DONE in 0.1.0]**: Trusted Publisher and `pypi` environment configured, CHANGELOG dated, versions bumped, `mgraphctl--v0.1.0` tagged, Release workflow green. Remaining: run the login → data-command flow on Windows; resolve the two spec open points.
6. **CI matrix and test isolation.** Add `macos-latest` and `windows-latest` to the test job; add mypy or pyright. `MGRAPHCTL_CLIENT_ID` is pinned in the autouse fixture since 0.1.0; `TENANT_ID`, `RETRIES`, `TIMEOUT_MS` and `RETRY_BASE_MS` are still inherited from the shell.
7. **Dependency hygiene.** Give `exclude-newer` an owner and cadence, or add `pip-audit`/`uv audit` plus Dependabot for msal/httpx/cryptography; add `SECURITY.md`.
8. **[CARRIED MINORS]** duplicated `_run` / `JSON` header dict / `_FRACTIONAL_RE` across graph modules (fold into `graph/_common.py`); underscore-prefixed planner annotations; `hit_cap` wording.
9. **[NOT SCHEDULED, nice to have]** machine-readable `schema` verb (mg-api / `gws` pattern) so agents and the SKILL.md can be generated from one registry; global `--query`/`--fields` projection; one-shot `meetings insights --subject`; measured token-cost comparison vs Softeria/Work IQ for the launch pitch; skills.sh layout; a thin MCP wrapper only if demand appears.

### 6.3 Phased plan

- **Phase 0 — first release**: done 2026-09-05 as 0.1.0 with the client-id guard and docs (item 1 in part) and the release pipeline (item 5). Items 2, 3 and 4 shipped unaddressed and move to Phase 1.
- **Phase 1 — hardening**: items 2–4, 6–7; a threat-model doc (token cache at rest, `api` verb, allow-list, hosted-content validation, fixture transport, `--debug` redaction, `$batch` partial failures, upload `.part` handling) compared against Softeria GHSA-9w34, Lokka CVE-2026-58201 and Kiota CVE-2026-44503; README sections for admin consent, own app registration, Windows, proxies, sovereign clouds (unsupported — say so).
- **Phase 2 — reach**: skills.sh / agentskills.io layout; shim → `uvx --from mgraphctl==X.Y.Z mgraphctl "$@"` with the marketplace pin bumped by the release skill; `.cmd` shim; a short "why a CLI, not an MCP" page with measured numbers.
